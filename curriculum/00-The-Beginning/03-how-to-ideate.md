# 03. 如何發想好題材 (Ideation: From Pain Points to Product)

很多初學者在學習編程時最痛苦的不是語法，而是 **「不知道要做什麼」**。他們往往會選擇做一個「待辦清單 (Todo List)」或「計算機」，但這些專案因為缺乏真實需求，很快就會失去動力。

專業工程師開發產品的起點不是「我想用這個技術」，而是 **「我想解決這個問題」**。

---

## 1. 從生活痛點出發 (Pain Point Analysis)

最好的題材永遠來自於你的**不便**。請試著在日常生活中尋找那些讓你覺得「如果能有一個工具幫我...就好了」的時刻。

### 案例研究：將痛點轉化為產品
想像一個使用者每天都要騎共享單車上學/上班，他會遇到以下痛點：
- **痛點 1**：官方 App 開啟速度慢 $\rightarrow$ **需求**：需要一個極速啟動的 Web 頁面。
- **痛點 2**：想知道最近的站點有沒有車 $\rightarrow$ **需求**：需要即時 API 數據。
- **痛點 3**：每次都要手動輸入站名 $\rightarrow$ **需求**：需要地理定位 (Geolocation) 自動推薦最近站點。
- **痛點 4**：某些站點總是沒車 $\rightarrow$ **需求**：需要「收藏/釘選」功能快速查看常用站點。

**練習：** 拿出一張紙，列出你今天遇到的 3 個小不便。
- *例子*：每天要對比三個電商平台的價格 $\rightarrow$ 題材：價格比對工具。
- *例子*：忘記藥物服用時間 $\rightarrow$ 題材：簡單的用藥提醒網頁。

---

## 2. 需求分析與功能拆解 (Feature Decomposition)

一旦有了方向，不要立刻開始寫程式碼。專業的流程是：**定義問題 $\rightarrow$ 拆解功能 $\rightarrow$ 規劃界面**。

### 功能拆解法 (Feature List)
將你的想法拆解為「必須有」和「有了更好」的功能：

| 優先級 | 功能名稱 | 描述 | 技術對應 (預測) |
| :--- | :--- | :--- | :--- |
| **核心 (Must)** | 基礎查詢 | 使用者輸入關鍵字，顯示結果清單 | HTML Input + JS Filter |
| **核心 (Must)** | 即時數據 | 顯示最新的數值/狀態 | API Fetch + DOM Update |
| **重要 (Should)** | 地圖視覺化 | 在地圖上標記出位置 | Map API |
| **重要 (Should)** | 自動定位 | 開啟頁面立即顯示附近資訊 | Geolocation API |
| **加分 (Could)** | 深色模式 | 讓使用者在夜晚使用時不刺眼 | CSS Variables + LocalStorage |
| **加分 (Could)**, | PWA 安裝 | 將網頁安裝到手機桌面 | Service Worker + Manifest |

---

## 3. MVP 概念：最小可行產品 (Minimum Viable Product)

很多開發者會陷入 **「功能陷阱」**：想把所有功能一次做完，結果因為太複雜而半途而廢。

**MVP 的核心是：只做最核心的功能，快速上線，快速獲取反饋。**

### 以「交通查詢工具」為例的 MVP 演進路徑：
- **V0.1 (極簡版)**：一個輸入框 $\rightarrow$ 呼叫 API $\rightarrow$ 用 `console.log` 印出結果。 (驗證 API 是否可用)
- **V0.2 (基礎版)**：將結果顯示在 HTML 列表中。 (驗證基本功能)
- **V0.3 (可用版)**：加入地理定位，直接顯示最近的 5 個結果。 (驗證核心價值)
- **V0.4 (專業版)**：加入地圖、深色模式、PWA 離線快取。 (優化體驗)

## 🛠️ 實作挑戰：規劃你的第一個專案

現在，請你嘗試為自己規劃一個小專案。請在你的筆記中回答以下問題：

1. **痛點是什麼？** (描述一個你生活中的不便)
2. **目標用戶是誰？** (是你自己？還是某類特定人群？)
3. **列出你的 MVP 功能清單** (至少 3 個核心功能)。
4. **這個專案可能會用到哪些技術？** (例如：需要定位嗎？需要存儲數據嗎？需要外部 API 嗎？)
